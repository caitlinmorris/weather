# V0.1 Plan — Replay First, Then Go Live

*Drafted with Claude Code after reading the five intro docs. Governing insight: ~27
real Claude Code sessions already sit in `~/.claude/projects/` (10 from the last
week, format verified parseable). The riskiest assumption in the whole project is
not capture plumbing — it's "can an extractor produce honest, colleague-appropriate
state from real transcripts?" That can be tested against existing history **today**,
with zero hooks, zero workers, zero live infrastructure.*

## The one proposed change to the build order

capture-overlay-architecture-v1 sequences live capture (hooks + worker) before
extraction. This plan inverts it: **batch replay of existing transcripts first,
live capture last.** Rationale:

- The data already exists; replay is idempotent and re-runnable while prompts and
  schema churn (they will churn — the plan itself predicts the schema "will be
  wrong in instructive ways").
- Live capture adds freshness, not learning. Every hard question (extraction
  quality, schema fit, gist tone, behavioral features) is answerable on history.
- The replay harness is not throwaway — it's the `simulate/` component already
  planned for week 4, pulled forward. Hooks land afterward and feed the same
  worker code path the replayer exercises.

## Milestone A — the spine (≈ days 1–4)

Prove: real transcript → SessionObservation, end to end, by hand-cranked batch.

1. **JSONL parser + canary test** (delegated). Narrow interface over the verified
   on-disk format; fails loudly on format drift.
2. **`schema.py`** (human-written, Claude reviews). Pydantic types straight from
   person-model-spec-v0.
3. **Two SQLite stores** (delegated). Private/public split as two files, per
   tech-spec-v0; only `rollup.py` gets the public write path.
4. **Segmenter** (delegated). 30-min-gap splitting over historical files.
5. **Extractor prompt v1** (human-written, designed in the Fable chat) + a thin
   harness (delegated) that runs it on 3–5 real sessions and pretty-prints the
   resulting SessionObservations for eyeballing.

**Exit test:** read five observations of your own real work. Are the gists
colleague-appropriate? Is `unknown` being used honestly? Gut-check before any
metrics.

## Milestone B — V0.1, the shareable artifact (≈ days 5–10)

**Definition: "a week of my work as weather."** Replay your own recent history
through the full pipeline and render it ambiently:

1. **`behavioral.py`** (human-written). Cadence, tool-call mix, failure streaks,
   edit→revert loops — over parsed historical events.
2. **Incremental extractor** (harness delegated, prompts human). Rolling
   delta-updates exactly as Appendix A describes, but with the replayer feeding
   deltas instead of a live worker — same interface, so the live worker later
   slots in without rework.
3. **`rollup.py` + PersonState timeline** (human-written rules, delegated glue).
   Output: a time series of published-tier PersonStates for the week.
4. **Pseudo-people split** — partition history by project directory into 3–4
   synthetic colleagues (already implied by week 4's simulation plan). This makes
   the *group* display demonstrable without recruiting anyone.
5. **Minimal renderer** — one surface only, fed by replayed GroupState with a
   time scrubber: drifting dots + staleness decay + the two-sentence weather
   line. Technology chosen by audience (open question 1 below).

**Why this is the right shareable:** it demonstrates every layer of the talk's
spine (person state → shared element → rendering) on real data, is privacy-safe
by construction (all one person's data, self-published), and needs no relay, no
consent flows, no installs by others.

## Milestone C — go live on self (≈ days 11–15)

Only after replay works: hook enqueue scripts, background worker with high-water
marks and debounce, statusline Ring 1 off solo GroupState. This is
capture-overlay-architecture-v1's plan, unchanged — just resequenced. From here
the original roadmap resumes (eval labeling, relay, Ring 2 TUI, pilot).

## Division of labor (per tech-spec-v0, to confirm)

Human-written: `schema.py`, `behavioral.py`, `similarity.py`, `rollup.py` rules,
all extractor prompts. Claude Code: parser, stores, segmenter, replayer, extractor
harness, renderer scaffold, tests. Open question 2 asks whether this holds
strictly from day 1 or relaxes for V0.1 speed.

## Prerequisites / setup

- `git init` + repo skeleton per tech-spec-v0 layout; `files/` → `docs/`;
  CLAUDE.md from the tech-spec draft.
- An Anthropic API key for the runtime extractor (Haiku-class; replaying a week
  of history ≈ a few hundred small calls — dollars, not tens).
- Privacy note for replay: historical transcripts include non-residency work
  (job docs, personal projects). The replayer should take an explicit
  allowlist of project directories rather than globbing everything.
